Part 1 · Array

Arrays are ordered lists &mdash; the structure you reach for whenever you have &ldquo;many of something&rdquo;: rows from a database, items in a cart, results from an API. This part covers their full method surface, grouped by what you&rsquo;re trying to do.

Creating & checking arraysCore#

In plain terms

An array is an ordered list of values, written with square brackets: [1, 2, 3]. Each value sits at a numbered position called an index, and counting starts at 0 — so the first item is at index 0, the second at 1, and so on. Before you work with something, you often need to make an array (from scratch, or from some other data) or check that what you have really is one. This section covers both.

You'll create arrays three main ways: the literal [ ] (by far the most common), Array.from() to build one from something iterable or array-like, and Array.of() for a quick list of known values. To verify you actually have an array — which matters because typeof [] === "object", unhelpfully — the one reliable test is Array.isArray().

Key terms in this section

Strict equality operator — compares two values and returns true only if they're the same type and value, with no automatic conversion. Your default for comparing.
==
Loose equality operator — compares two values after converting them to a common type, which causes surprises. Avoid in favour of ===.
=>
Arrow — defines an arrow function, a short way to write a function (e.g. x => x * 2). The arrow separates the inputs from what the function does.
**
Exponentiation operator — raises a number to a power (2 ** 3 is 8).
array-like
Array-like — an object with a length and numbered keys but no array methods (e.g. a DOM NodeList); convert with Array.from.
iterable
Iterable — any value you can step through one item at a time with for…of (arrays, strings, Maps, Sets).
promise
Promise — an object standing in for a value that isn't ready yet; it later succeeds or fails.
index
Index — an item's numbered position in an array or string, starting at 0.
Array.from with a map function is a clean way to generate a sequence — handy for building ranges or placeholder rows.

const nums = [1, 2, 3];                 // array literal — the everyday way
const empty = [];                       // empty, ready to fill
const rows = Array.from(nodeList);      // make a real array from array-like/iterable
const chars = Array.from("hi");         // ["h", "i"]
const mapped = Array.from({length: 3}, (_, i) => i * 2);  // [0, 2, 4]
const few = Array.of(7);                // [7]  (Array(7) would make 7 empty slots!)

Array.isArray(nums);                    // true  — the reliable check
typeof nums;                            // "object" — why isArray exists
nums.length;                            // 3  — count of items
Gotcha new Array(3) creates an array with 3 empty slots, not [3] — a classic trap. Use Array.of(3) for a single-element array, and the literal [ ] for everything else. Empty slots ("holes") also behave oddly with some methods, so avoid them.
When to use Arrays exist to hold an ordered collection where position matters and duplicates are fine — a feed of posts, a queue of jobs, the rows of a table. When you instead need fast lookup by a unique key, or guaranteed-unique values, reach for Map/Set (later in this book). Use Array.from specifically to convert the array-like things the browser hands you (a NodeList from the DOM, the arguments object) into real arrays so the full method toolbox below becomes available.

Adding, removing & reorderingCore#

In plain terms

Once you have an array, you'll constantly add items to it, take items out, and change their order. Two important words here: a method that mutates changes the original array in place; a method that returns a new array leaves the original untouched. Knowing which is which prevents a whole category of bugs, so each item below is labeled.

The mutating workhorses are push/pop (add/remove at the end) and shift/unshift (at the start), plus splice (insert/remove anywhere) and sort/reverse (reorder). They all change the array in place and are perfect when you own the array. When you must not mutate (shared state, UI data), use the immutable equivalents in the Copying & immutable updates section.

Key terms in this section
=>
Arrow — defines an arrow function, a short way to write a function (e.g. x => x * 2). The arrow separates the inputs from what the function does.
**
Exponentiation operator — raises a number to a power (2 ** 3 is 8).
comparator
Comparator — a function you give sort that returns negative/zero/positive to decide the order of two items.
immutable
Immutable update — making a new value with the change instead of altering the original.
argument
Argument — the actual value you pass into a function when you call it.
mutate
Mutate — to change a value in place; a mutating method alters the original array/object.
index
Index — an item's numbered position in an array or string, starting at 0.
push/pop at the end are fastest; shift/unshift at the start are slower because every other item must shift position.

const stack = [];
stack.push("a", "b");     // add to END   -> ["a","b"]   (returns new length)
stack.pop();              // remove from END -> returns "b"

const queue = ["x", "y"];
queue.shift();            // remove from START -> returns "x"
queue.unshift("w");       // add to START -> ["w","y"]

const list = [1, 2, 3, 4, 5];
list.splice(1, 2);        // remove 2 items from index 1 -> list is [1,4,5]
list.splice(1, 0, 9);     // insert 9 at index 1 (remove 0) -> [1,9,4,5]

[3, 1, 2].sort();                  // [1,2,3]  but BEWARE default is string order
[3, 1, 2].sort((a, b) => a - b);   // [1,2,3]  numeric — pass a comparator
["a","b"].reverse();               // ["b","a"]  (mutates)
Gotcha .sort() with no argument converts items to strings and sorts by character code — so [10, 9, 100].sort() gives [10, 100, 9]. For numbers, always pass a comparator: .sort((a, b) => a - b). Note sort and reverse mutate; use toSorted/toReversed (immutable, ES2023) when you must not change the original.
When to use These mutating methods exist because changing a list in place is efficient and natural when the array is yours — building up a result, managing a stack or queue. The danger is only when an array is shared: if another part of the app holds the same array (very common with UI state), mutating it changes their copy too, causing bugs that are hard to trace. Rule of thumb: mutate freely on arrays you just created locally; switch to the immutable versions for anything passed in or stored in shared state.

Removes and returns the last item. Pairs with push to use an array as a stack.

Adds to the start. Returns new length. Slower than push (shifts all items).

Removes and returns the first item. Pairs with push to use an array as a queue.

Swiss-army knife: removes delCount items at start and/or inserts new ones. Returns the removed items. Mutates.
.fill()arr.fill(value, start?, end?)
Overwrites a range with a fixed value. new Array(3).fill(0) → [0,0,0].
.copyWithin()arr.copyWithin(target, start, end?)
Copies part of the array to another position within itself. Rare.

.reverse()arr.reverse()
Reverses order in place.

Finding & testingCore#

In plain terms

Often you don't want the whole list — you want one item out of it, or a yes/no answer about it. "Is there a user with this id?" "Does every field pass validation?" "Where is this item?" These methods answer those questions. Most take a small function (a callback) that you use to describe what you're looking for.

To get an item, use find (the item itself) or findIndex (its position). To get a yes/no, use includes (is this exact value present?), some (does any item pass?), or every (do all items pass?). These read almost like English and replace a lot of manual loops.

Key terms in this section
===
Strict equality operator — compares two values and returns true only if they're the same type and value, with no automatic conversion. Your default for comparing.
==
Loose equality operator — compares two values after converting them to a common type, which causes surprises. Avoid in favour of ===.
=>
Arrow — defines an arrow function, a short way to write a function (e.g. x => x * 2). The arrow separates the inputs from what the function does.
...
Spread/rest operator (three dots) — either spreads a collection out into its items, or gathers loose items into one collection, depending on where it's used.
**
Exponentiation operator — raises a number to a power (2 ** 3 is 8).
short-circuit
Short-circuit — stopping early once the answer is known (some stops at first match, every at first failure).
callback
Callback — a function you pass to a method (like map or filter) for it to call on each item.
index
Index — an item's numbered position in an array or string, starting at 0.
NaN
NaN ("Not a Number") — the result of an invalid math operation, like 0/0.
find/some/every take a test function; includes/indexOf take a plain value. Reach for the function versions when matching on a property.

const users = [{id:1,active:true},{id:2,active:false},{id:3,active:true}];

users.find(u => u.id === 2);        // {id:2, active:false}  — first match, or undefined
users.findIndex(u => u.id === 2);   // 1  — position, or -1 if none
users.findLast(u => u.active);      // {id:3,...}  — search from the END (ES2023)

[1, 2, 3].includes(2);              // true   — exact value present? (uses ===)
users.some(u => !u.active);         // true   — is ANY user inactive?
users.every(u => u.active);         // false  — are ALL users active?

[1, 2, 3].indexOf(2);               // 1   — position of an exact value (or -1)
Gotcha includes and indexOf compare with strict equality, so they find primitives but not equivalent objects: [{id:1}].includes({id:1}) is false (different object references). To find an object by its contents, use find with a test: arr.find(o => o.id === 1). Also, indexOf(NaN) never finds NaN — includes(NaN) does.
When to use These exist to make intent obvious and to short-circuit — some stops at the first match, every stops at the first failure, so they're efficient as well as readable. Before them, every "does any row…?" check was a hand-written loop with a flag variable; some/every say the same thing in one line. Use find over filter()[0] when you only want one result — filter always scans the whole array and builds a new one, while find stops as soon as it hits a match.

Returns the first item for which the test returns true, or undefined. The go-to for "get the record where…".
.findIndex()arr.findIndex(testFn)
Like find but returns the index (or -1). Use when you need the position, e.g. to replace or remove.
.findLast()arr.findLast(testFn)
Searches from the end. Returns the last match. ES2023.
.findLastIndex()arr.findLastIndex(testFn)
Index version of findLast. ES2023.
.indexOf()arr.indexOf(value, from?)
First index of an exact value (===), or -1. For values, not tests.
.lastIndexOf()arr.lastIndexOf(value)
Last index of an exact value.

Item at an index, with negative support: arr.at(-1) is the last item — cleaner than arr[arr.length-1]. ES2022.
Yes / no questions

true if an exact value is present. Correctly finds NaN. For primitives.

Transforming arraysCore#

In plain terms

This is the heart of working with data in JavaScript. Instead of writing loops, you transform one array into another with three core methods. map makes a new array by changing every item ("give me just the names"). filter makes a new array keeping only items that pass a test ("only the active users"). reduce boils the whole array down to a single value ("the total price"). They don't change the original — each returns a fresh array (or value).

map, filter, and reduce are the backbone of data work — rendering lists in UIs, shaping API responses, computing summaries. They chain: data.filter(...).map(...) reads as a pipeline of steps. Because they return new arrays and never mutate, they fit perfectly with state-driven UIs. Learn these three cold; the rest of this book leans on them.

Key terms in this section
=>
Arrow — defines an arrow function, a short way to write a function (e.g. x => x * 2). The arrow separates the inputs from what the function does.
...
Spread/rest operator (three dots) — either spreads a collection out into its items, or gathers loose items into one collection, depending on where it's used.
**
Exponentiation operator — raises a number to a power (2 ** 3 is 8).
accumulator
Accumulator — in reduce, the running result carried from one item to the next.
mutate
Mutate — to change a value in place; a mutating method alters the original array/object.
index
Index — an item's numbered position in an array or string, starting at 0.
rest
Rest — using ... to collect several values into a single array or object.
map and filter each return a new array, so they chain. reduce is the most general — map and filter can both be written as a reduce, but the named ones read better.

const products = [
  {name: "Pen",   price: 2, inStock: true},
  {name: "Desk",  price: 200, inStock: false},
  {name: "Lamp",  price: 40, inStock: true},
];

// map — transform every item into something new
const names = products.map(p => p.name);          // ["Pen","Desk","Lamp"]
const withTax = products.map(p => ({...p, price: p.price * 1.1}));

// filter — keep only items that pass the test
const available = products.filter(p => p.inStock); // Pen & Lamp

// reduce — collapse to a single value (sum, object, anything)
const total = products.reduce((sum, p) => sum + p.price, 0);   // 242
// the 0 is the STARTING value (the "accumulator")

// chain them into a pipeline:
const inStockNames = products
  .filter(p => p.inStock)
  .map(p => p.name);                               // ["Pen","Lamp"]

flatMap & flat — when items expand into lists

flatMap is map followed by a one-level flat — ideal when each item produces several results you want in one flat list.

const orders = [{items:["a","b"]}, {items:["c"]}];
orders.flatMap(o => o.items);     // ["a","b","c"]  — map then flatten one level
[1, [2, [3]]].flat();             // [1, 2, [3]]    — flatten one level
[1, [2, [3]]].flat(Infinity);     // [1, 2, 3]      — flatten all levels
Gotcha reduce without a starting value uses the first element as the initial accumulator and can throw on an empty array — always pass the initial value (, 0 or , {} or , []). Also, inside map/filter callbacks, returning nothing gives undefined — for map, remember to actually return the new value (or use a concise arrow without braces).
When to use These exist to make data transformation declarative — you say what you want, not the mechanics of looping and pushing. The payoff is threefold: the code reads as a description of the result, there's no manual index bookkeeping to get wrong, and because nothing is mutated, the same input always gives the same output (easy to reason about and test). This is why modern JavaScript favors them over for loops for shaping data: a .filter().map() pipeline is the standard way data flows through a UI. Drop back to a real loop only when you need to break early or await each step.
The core three
.map()arr.map(fn)
Returns a new array with fn applied to each item. "Transform every element." Same length as the original.
.filter()arr.filter(testFn)
Returns a new array of only the items that pass the test. "Keep the ones that match."
.reduce()arr.reduce(fn, initial)
Collapses the array to a single value by accumulating. fn(accumulator, item) runs per element. Always pass initial. The most general transform.
.reduceRight()arr.reduceRight(fn, initial)
Like reduce but processes right-to-left. Niche.
.flatMap()arr.flatMap(fn)
map then flatten one level — for when each item yields several results.
.flat()arr.flat(depth?)
Flattens nested arrays by depth levels (default 1). flat(Infinity) fully flattens. ES2019.

Iterating & joiningCore#

In plain terms

Sometimes you don't want to build a new array — you just want to do something with each item (log it, render it, send it), or turn the list into a single string. These methods walk the array for those purposes.

forEach runs a function for every item purely for its side-effects (it returns nothing). join turns an array into a string with a separator. keys/values/entries give you iterators for use in for…of loops, with entries handing you index-and-value pairs.

Key terms in this section
=>
Arrow — defines an arrow function, a short way to write a function (e.g. x => x * 2). The arrow separates the inputs from what the function does.
**
Exponentiation operator — raises a number to a power (2 ** 3 is 8).
side-effect
Side-effect — a change to something outside the function (logging, updating the DOM) rather than returning a value.
iterator
Iterator — an object that produces values one at a time via .next(); what keys/values/entries return.
index

join is the clean way to build text from a list — far better than string concatenation in a loop.

["a","b","c"].forEach((item, i) => console.log(i, item));  // side-effects only

["a","b","c"].join(", ");      // "a, b, c"   — array -> string
["a","b","c"].join("");        // "abc"
[1,2,3].join(" / ");           // "1 / 2 / 3"

for (const [i, val] of ["x","y"].entries()) {  // index + value together
  console.log(i, val);         // 0 "x", then 1 "y"
}
Gotcha forEach cannot be stopped early (no break) and does not wait for await inside it — if you need either, use a for…of loop instead. Also, forEach returns undefined, so it can't be chained like map/filter. If you find yourself building a result inside forEach, you probably want map, filter, or reduce.
When to use forEach exists for the case where you genuinely only want a side-effect for each item and aren't producing a new array — though in practice a for…of loop is often clearer and more capable (it supports break and await). join exists because building strings from lists is so common, and doing it with += in a loop is both slower and more error-prone (stray separators). Reach for join any time you're turning a list into displayable or storable text — CSV rows, comma lists, URL query parts.

Copying & immutable updatesCore#

In plain terms

A reminder from Book 1: arrays are shared by reference, so handing your array to another function lets it change your copy. The safe pattern is to make a new array with the change rather than altering the original — this is called an immutable update, and it's how state-driven apps (like React) avoid a whole class of bugs. This section gathers the tools for copying and for the newer "change but return a copy" methods.

For copies: spread [...arr] and slice() make shallow copies; concat joins arrays into a new one. For immutable edits, ES2023 added toSorted, toReversed, toSpliced, and with — the copying twins of sort, reverse, splice, and index assignment. They do the same job without touching the original.

==

=>

...
Spread/rest operator (three dots) — either spreads a collection out into its items, or gathers loose items into one collection, depending on where it's used.
**
Exponentiation operator — raises a number to a power (2 ** 3 is 8).
reference
Reference — a pointer to an object; copying it copies the pointer, so two names can share one object.
deep copy
Deep copy — a fully independent duplicate, including nested objects (structuredClone).
shallow

mutate

The to… methods and with are the immutable versions of the mutating ones — same operation, fresh array. Perfect for updating state without side-effects.

const original = [3, 1, 2];

// shallow copies
const copy = [...original];          // spread — the usual way
const copy2 = original.slice();      // slice with no args — same effect
const joined = original.concat([4]); // new array [3,1,2,4]

// immutable edits (ES2023) — return a NEW array, original untouched:
const sorted = original.toSorted((a,b) => a-b);  // [1,2,3]; original still [3,1,2]
const reversed = original.toReversed();          // [2,1,3]
const replaced = original.with(0, 99);           // [99,1,2]  (index 0 -> 99)
const spliced = original.toSpliced(1, 1);        // [3,2]     (remove index 1)

// immutable "append" / "remove" with spread + filter:
const added = [...original, 4];
const removed = original.filter(x => x !== 1);
Gotcha All these copies are shallow — the new array is independent, but objects inside it are still shared with the original. Changing copy[0].name also changes original[0].name. For a fully independent deep copy, use structuredClone(arr).
When to use These exist to make "change without mutating" easy. Before ES2023, sorting a prop without wrecking the original meant [...arr].sort() — copy first, then mutate the copy. toSorted and friends express that intent directly and avoid the easy mistake of forgetting the copy. Why it matters so much in UI code: frameworks detect changes by comparing whether the array reference changed; if you mutate in place the reference is the same and the UI may not update, but if you produce a new array it re-renders correctly. So immutable updates aren't just tidy — they're often required for the screen to refresh.
Version toSorted, toReversed, toSpliced, and with are all ES2023. structuredClone is a relatively recent global (Node 17+, all modern browsers) for true deep copies.

Part 2 · String

Text is everywhere in an app &mdash; names, messages, URLs, user input, IDs. Strings are how you hold and shape it. This part covers the full method surface for inspecting, slicing, cleaning, and splitting text.

Inspecting & searching stringsCore#

In plain terms

A string is a piece of text, written in quotes: "hello", 'hi', or ` hey `. Strings are immutable — every method that "changes" a string actually returns a new one and leaves the original alone. Before doing anything with text, you often need to ask questions about it: how long is it? does it contain this word? does it start with that prefix? These methods answer those.

The everyday checks are includes (does it contain this?), startsWith/endsWith (prefix/suffix tests — great for file extensions, URL checks), and indexOf (where is this substring?). length gives the character count. These read clearly and replace fiddly manual checks.

Part 5 · Keyed Collections

When a plain object isn&rsquo;t the right shape for your data, these purpose-built collections are: <code>Map</code> for key&ndash;value pairs with any kind of key, <code>Set</code> for unique values, and their <code>Weak</code> variants for memory-friendly associations.

MapCore#

In plain terms

A Map is a collection of key→value pairs, like an object — but better suited when you're using it as a dictionary you constantly add to and remove from. Unlike objects, a Map's keys can be any type (objects, numbers, not just strings), it remembers insertion order, it has a .size, and it's built for frequent changes. You create one with new Map().

WeakMap & WeakSetReference#

In plain terms

These are special, memory-friendly versions of Map and Set. Part 6 · JSON

JSON is the universal text format for data exchange &mdash; what APIs send, what you save to storage, what config files use. Two methods do all the work: one turns data into JSON text, the other turns JSON text back into data.

JSONCore#

In plain terms

JSON (JavaScript Object Notation) is a way of writing data as plain text so it can be sent over the internet or saved to a file. It looks almost exactly like a JavaScript object. The catch: a live JavaScript object lives in memory, while JSON is text. You stringify to go from object → text (to send or store it), and parse to go from text → object (when it comes back).

JSON.stringify(value) converts data to a JSON string. JSON.parse(text) converts a JSON string back to data. This is the boundary you cross every time you talk to a server (fetch), use localStorage, or read a config file. Both have optional extra arguments for formatting and transforming.

Part 7 · Dates & Internationalization

Working with time and with formatting for human readers. <code>Date</code> represents moments in time; <code>Intl</code> formats dates, numbers, and currency correctly for any language and region.

DateCore#

In plain terms

Part 8 · RegExp

Regular expressions are a compact language for describing text patterns &mdash; matching, validating, and extracting. They&rsquo;re powerful but terse; this part gives you the working core and points to where the deep detail lives.

Regular expressionsReference#

In plain terms

A regular expression (regex) is a pattern for matching text — a way to say "a string that looks like this" without writing it all out. You write one between slashes: /\d+/ means "one or more digits." Regexes can check if text matches a shape (is this a valid email?), find parts of it, or replace patterns. They're famously cryptic, so the goal here is the practical core, not mastery of every symbol.

You'll use regexes mainly in three string methods: test (does it match? true/false), match/matchAll (extract what matched), and replace/replaceAll (swap matches out). The pattern itself is built from literal characters plus special symbols for "any digit," "one or more," "start of string," and so on. Flags after the closing slash (g global, i case-insensitive) modify behavior.

Part 9 · Promise (static methods)

Book 1 covered how promises and <code>async</code>/<code>await</code> work. This part is the <em>toolbox</em>: the static <code>Promise.*</code> methods that combine several promises into one &mdash; the everyday tools for running async work in parallel.

Promise combinatorsCore#

In plain terms

A reminder: a promise represents a value that isn't ready yet (a network request in flight). Often you have several of these at once — three API calls, a batch of file reads — and you want to wait for them as a group rather than one-by-one. The Promise.* combinators are static methods (called on Promise itself) that take an array of promises and combine them into a single promise you can await.

Promise.all is the workhorse: run everything in parallel, get all results, fail if any one fails. Promise.allSettled is its tolerant sibling: wait for all and report each as success or failure. Promise.race and Promise.any resolve on the first to finish or first to succeed. Choosing the right one is mostly about how you want failures handled.

Key terms in this section
===
Strict equality operator — compares two values and returns true only if they're the same type and value, with no automatic conversion. Your default for comparing.
==
Loose equality operator — compares two values after converting them to a common type, which causes surprises. Avoid in favour of ===.
=>
Arrow — defines an arrow function, a short way to write a function (e.g. x => x * 2). The arrow separates the inputs from what the function does.
**
Exponentiation operator — raises a number to a power (2 ** 3 is 8).
fulfilled
Fulfilled — a promise that has succeeded and now holds a value.
rejected
Rejected — a promise that has failed and now holds an error.
static
Static member — a property or method that belongs to the class itself, not to individual instances.
If async tasks don't depend on each other, Promise.all runs them together — awaiting them one-by-one instead is a common, invisible performance bug.

// run in PARALLEL and collect all results (fails fast if any reject):
const [user, posts, prefs] = await Promise.all([
  fetch("/api/user").then(r => r.json()),
  fetch("/api/posts").then(r => r.json()),
  fetch("/api/prefs").then(r => r.json()),
]);   // all three requests fly at once — much faster than awaiting in sequence

// tolerate partial failure — get status for each:
const results = await Promise.allSettled(tasks);
results.forEach(r => {
  if (r.status === "fulfilled") use(r.value);
  else log(r.reason);          // this one failed, others still ran
});

// first to SUCCEED wins (e.g. fastest mirror); ignores individual failures:
const fastest = await Promise.any([fetchA(), fetchB()]);

// first to SETTLE wins, success or failure (e.g. timeout pattern):
const out = await Promise.race([work(), timeout(5000)]);

// build a promise you resolve elsewhere (ES2024):
const {promise, resolve, reject} = Promise.withResolvers();
Gotcha Promise.all rejects as soon as any promise rejects, and you lose the results of the ones that succeeded — use Promise.allSettled when you need every result regardless. Promise.race settles on the first to finish whether it succeeded or failed, so a fast rejection wins the race — that's different from Promise.any, which waits for the first success. Passing non-promise values is fine (they're treated as already-resolved).
When to use These exist to express parallelism cleanly. The naive way to handle several async operations is to await them one after another — but if they're independent, that wastes time waiting for each to finish before starting the next. Promise.all starts them all at once and waits for the group, often turning three sequential 200ms requests into a single 200ms wait. The variants exist because real systems fail: allSettled when partial success is acceptable (load what you can), any for redundancy (first working source), race for timeouts (whichever finishes first). Knowing which combinator to reach for is a core backend/data skill — and it carries directly into the data-intensive API book later, where batching parallel work is central.
Version Promise.all/race are ES2015; Promise.allSettled is ES2020; Promise.any is ES2021; Promise.withResolvers() is ES2024; Promise.try() is ES2025.

SymbolReference#

In plain terms

A Symbol is a guaranteed-unique value. Every symbol you create is different from every other, even one made with the same description. Their main job is to serve as object keys that can never accidentally collide with another key — useful for adding "hidden" properties or for hooking into special language behaviors.

You create one with Symbol("description"). Because each is unique, they're used as non-colliding keys and to implement language protocols — most importantly Symbol.iterator, which is what makes an object work with for…of (you saw this in Book 1's iteration topic).

Key terms in this section
===
Strict equality operator — compares two values and returns true only if they're the same type and value, with no automatic conversion. Your default for comparing.
==
Loose equality operator — compares two values after converting them to a common type, which causes surprises. Avoid in favour of ===.
...
Spread/rest operator (three dots) — either spreads a collection out into its items, or gathers loose items into one collection, depending on where it's used.
**
Exponentiation operator — raises a number to a power (2 ** 3 is 8).
iterable
Iterable — any value you can step through one item at a time with for…of (arrays, strings, Maps, Sets).
iterator
Iterator — an object that produces values one at a time via .next(); what keys/values/entries return.
spread
Spread — using ... to expand a list or object into its individual pieces.
Symbols are mostly something you use via well-known ones like Symbol.iterator rather than create yourself — they're a building block library authors lean on more than app developers.

const id = Symbol("id");

Symbol("x") === Symbol("x");    // false — every symbol is unique

// the well-known symbol you'll actually use — make an object iterable:

When to use Symbol exists to solve key collisions: if a library adds a property to your object using a string key, it might clobber yours (or vice versa); a symbol key is guaranteed unique, so it's safe for metadata and internal state. The well-known symbols (Symbol.iterator, Symbol.asyncIterator) exist so the language can let objects opt into behaviors — defining [Symbol.iterator] is literally how you make something work with for…of and spread. In everyday app code you'll mostly encounter symbols through these protocols rather than creating your own.

Iterator helpersReference#

In plain terms

Book 1 introduced iterables (things you can for…of over). Iterator helpers (new in ES2025) bring the familiar array methods — map, filter, take — directly to iterators, so you can process sequences lazily: one item at a time, computing only what you need, without first building a whole array. This is especially powerful for huge or infinite sequences.

Where array.map().filter() builds a new array at each step, iterator helpers form a lazy pipeline: nothing is computed until you pull values out, and take(n) can stop early — so they work on infinite generators and very large data without exhausting memory. You get them from any iterator (e.g. array.values(), a generator, map.keys()) or via Iterator.from().

  .filter(n => n % 2 === 0)
  .map(n => n * 10)
  .take(3)
  .toArray();              // [20, 40, 60]

Iterator helpers instead pull one value through the whole chain at a time and can stop early, making them ideal for processing large files line-by-line, paginated API results, or generated sequences. This connects directly to the data-intensive work later in the series, where streaming rather than buffering is the whole game.

Error typesCore#

In plain terms

Book 1 covered try/catch/throw. This is the family of built-in Error objects you actually throw and catch. Error is the base; specific types like TypeError and RangeError describe what kind of thing went wrong, so a catch block can react differently to different failures.

You'll mostly throw the generic Error with a clear message, and create custom subclasses for your app's own failure types. The built-in subclasses (TypeError, RangeError, SyntaxError) are thrown automatically by the language and are also useful to throw yourself for precise meaning. Every error carries message, name, and a stack trace.

    super(message);

Binary dataReference#

In plain terms

Most of the time you work with numbers, strings, and objects. But sometimes you handle raw binary data — bytes from a file, an image, a network stream, audio. Typed arrays (like Uint8Array) are array-like views over raw memory (an ArrayBuffer) that let you read and write those bytes efficiently. This is a specialized corner you'll meet mainly when dealing with files, streams, or performance-critical data.

An ArrayBuffer is a fixed block of raw bytes; a typed array (Uint8Array, Float64Array, etc.) is a typed window onto it that you index like a normal array. You'll encounter them when reading files (await blob.arrayBuffer()), handling binary network data, or working with the data-intensive streaming covered later in the series.

Key terms in this section
**
Exponentiation operator — raises a number to a power (2 ** 3 is 8).
array-like
Array-like — an object with a length and numbered keys but no array methods (e.g. a DOM NodeList); convert with Array.from.
index
Index — an item's numbered position in an array or string, starting at 0.
TextEncoder/TextDecoder convert between strings and raw bytes (UTF-8) — the bridge you'll use most when binary data is really text.

const buffer = new ArrayBuffer(8);     // 8 raw bytes

bytes[0] = 255;
bytes.length;                          // 8

// from a normal array, and back:
const u8 = Uint8Array.from([1, 2, 3]);
Array.from(u8);                        // [1, 2, 3]

// where you actually meet them:
const data = new Uint8Array(await blob.arrayBuffer());  // file bytes
const text = new TextDecoder().decode(data);            // bytes -> string
const back = new TextEncoder().encode("hi");            // string -> bytes
When to use Typed arrays exist because JavaScript's normal arrays are flexible objects, not efficient byte storage — fine for app data, wrong for megabytes of image pixels or audio samples. Typed arrays give you compact, fixed-type, memory-efficient storage that maps directly onto how files, network protocols, and hardware represent data. You'll meet them when reading uploaded files, processing streams, decoding binary formats, or squeezing performance out of large numeric datasets — which is exactly the territory of the data-intensive API and automation books later. For everyday work, you rarely need them; recognize them and know they're the tool when raw bytes appear.
